# 开发与测试

本仓库的 `skills/` 是正式技能源码。安装单项技能时复制相应完整目录；本地加载 Claude 插件时，传入包含 `.claude-plugin/` 和 `skills/` 的仓库根目录。

## 目录

| 路径 | 用途 |
|---|---|
| `skills/` | 十三项技能、参考材料、模板及运行脚本 |
| `.claude-plugin/` | 本地插件和市场清单 |
| `docs/` | 入门、开发和验收说明 |
| `hooks/` | 安装后第一次会话展示短说明 |
| `licenses/` | 完整文档许可文本 |
| `tests/` | 自动化回归和发行结构检查 |
| `README.md` | 安装入口与能力说明 |
| `ROADMAP.md` | 当前进度和待办 |
| `docs/维护约定.md` | 修改源码时遵循的约定 |

运行脚本只使用 Python 标准库。完整开发检查使用 Python 3.10 或更新版本，另需 PyYAML；最低版本及其他操作系统尚未逐一实机测试。

## 安装开发依赖

以下命令在仓库根目录执行。已有合适环境时无需重复创建。

```bash
python3 -m venv ".venv"
source ".venv/bin/activate"
python3 -m pip install -r "requirements-dev.txt"
```

Windows 使用 `py -m venv ".venv"` 创建环境，在 PowerShell 中执行 `.\.venv\Scripts\Activate.ps1`，后续命令使用该环境的 `python`。

## 运行检查

```bash
python3 -B -m unittest discover -s "tests" -v
python3 -B "tests/validate_package.py" "."
```

回归测试使用系统临时目录和合成材料，验证建库的新增与拒绝覆盖、路径边界、排版正文与媒体保真、HTML 报告字段与输出边界，以及发行检查器的异常输入。`validate_package.py` 检查正式发行文件的结构、相对引用、私人路径和凭据残留、运行脚本依赖及许可；它不把开发测试当作技能的运行依赖，也不能代替人工隐私审查。

已安装 Claude Code 时，可额外检查两份清单。该步骤只校验清单，不安装插件：

```bash
claude plugin validate --strict ".claude-plugin/plugin.json"
claude plugin validate --strict ".claude-plugin/marketplace.json"
```

## 修改与验收

技能正文保持简短，详细规范放在对应 `references/`；示例使用合成或已获公开授权的材料。改变引用或目录后运行发行检查，改变脚本后运行相关回归。定位报告涉及布局和交互时，还应实际打开生成的 HTML，检查手机布局、复制、证据展开与打印。

提交前检查将要纳入版本控制的文件，排除凭据、本机配置、历史原料、对话和临时生成物。`.gitignore` 只能阻止未跟踪文件被常规加入，不能清除已经提交的内容。

测试通过范围和仍未验证的环境见 [验收说明](验收说明.md) 。
