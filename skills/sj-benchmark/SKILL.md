# 叁斤·对标笔记拆解

## 一条铁律：拆的是原因，不是形式

**大部分人拆对标只拆到「它用了什么句式」，这没用。**同样的句式换个人写就不爆。要拆的是：它为什么能让那群人停下来。

拆完必须能回答一句话：**这篇爆是因为角度，还是因为节奏，还是因为平台给了流量？**答案不同，能不能迁移完全不同——角度可迁移，节奏可学，平台流量学不来。

## 开工前先读

用户有知识库就先读这三份，没有就问一句他是谁、写给谁：

1. `说明书/我是谁.md`：迁移到他身上时，他的身份决定哪些角度能用。
2. `说明书/我的客户.md`：对标的人群和他的人群差多少。
3. `说明书/我的内容标准.md`：判断这篇好不好，用他自己的标准，不用点赞数。

对标内容只拿用户给的：粘贴的正文、截图、链接里能读到的部分。链接打不开就请他把标题、正文和数据贴过来，不假装看过。

## 四种用法

| 用法 | 输入 | 做什么 |
|---|---|---|
| 单篇拆解 | 一篇笔记（正文或截图） | 走完拆解五步，再问要不要仿写 |
| 只仿写 | 一篇笔记＋用户的方向 | 跳过第 1、2 步，直接定档迁移 |
| 批量拆解 | 多篇笔记 | 逐篇走第 1—3 步，最后横向对比找共性；不仿写 |
| 账号拆解 | 一个账号近期的笔记 | 拆近期 5—10 篇，看选题规律和爆款集中在哪 |

## 拆解五步

做法见 [拆解五步](references/拆解五步.md)：

1. **还原它写给谁**：假设的读者是什么处境，它满足的是让人爽（点赞）、让人信（关注）还是让人抄（收藏）。
2. **拆四个零件**：人群、场景、冲突、落点；同时把风格、故事、叙事、情绪四层看得见的证据分开记。
3. **判断爆的原因**：角度、节奏、平台，逐个排除。
4. **用用户自己的标准打分**：先说它哪条不合格——爆款也有一堆不合格的地方，那些地方就是用户的机会。
5. **迁移成用户的选题**：按 [迁移与仿写](references/迁移与仿写.md) 先定档，再出迁移结果。

## 执行纪律

1. **拆解结果先给用户看，确认后才仿写**；仿写方向（推荐流笔记还是搜索笔记）由用户定。
2. **没答出「爆的原因」之前，不许开始仿写。**
3. **仿写不等于洗稿**：复用的是框架和关系，不是原文的句子和案例。
4. **不要只看数据**：点赞高不等于对用户有用。有些内容让人爽（点赞），有些让人信（关注）；做获客要学后者。
5. **只根据看得见的东西下结论**：正文、图片、视频画面、公开数据、评论原话。风格、故事、叙事、情绪四层分开判断，每条结论写清证据在第几段、第几张图、第几秒；不知道作者为什么这么写，就只写这一段起了什么作用，不替作者猜动机。
6. **素材不够就标出来**：迁移到用户身上缺的事实，标「需补」，不拿对标的细节当他自己的。
7. **对标是后厨，不上桌**：仿写出来的内容里，不出现「我刷到一条笔记」「有个博主说」「评论区有人说」。区分只有一句：这件事是查来的，还是用户自己遇上的——遇上的照写。
8. **批量拆解时不仿写**，哪篇值得深挖，提醒用户单独拆。

## 交付

拆解结果在对话里给。迁移出的选题，用户说「入库」再按 sj-topics 的选题卡格式存进 `选题库/`；仿写的正文交给 sj-xhs-viral（推荐流）或 sj-xhs-seo（搜索），按对应技能的格式交付和保存。拆的过程中发现值得长期留下的通用写法，交给 sj-learning 写进 `方法论/`。完整示例见 [完整示例](references/完整示例.md)。
