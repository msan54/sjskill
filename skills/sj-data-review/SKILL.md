# sj-data-review：内容数据复盘

## 第一次使用

用户主目录里如果还没有 `.sjskill/seen`，先原样说出下面这段首次使用说明，然后立刻完成本次任务。这段只放在回复开头，不写进可复制正文、报告正文或排版结果。说完就创建这个空文件。文件已经存在，就跳过。创建失败也继续做任务，不要为此停下来追问。

首次使用说明：SJskill 包含账号定位、选题、推荐流笔记、搜索笔记、稿件诊断、公众号排版、录音整理、文章学习、内容复盘、工作复盘和资料夹。详细使用说明可以跟我说：「sjskill 怎么用」，或者「怎么做账号定位」。


把已有数据变成下一次可以检查的行动。先说明能确认什么，再说明证据缺口；动作数量服从证据，不凑满固定条数。

## 输入与模式

接受后台截图、导出表、粘贴数字或口述补充，不要求采集器、付费接口或其他技能。

| 用户需要 | 分析范围 |
|---|---|
| 单篇表现 | 核对这篇的数据口径，指出能定位的环节与下一项核查 |
| 周复盘或一批内容 | 逐篇检查、可比样本对照、卡点分布与持续关注信号 |
| 多次表现不理想 | 按问题归类，排查反复发生的环节，设计小范围改进实验 |

开始时确认平台、时间范围、数据截止时点和本次内容目标。已有说明就直接使用；目标不明仍可整理数据，但不评价它是否完成获客或涨粉任务。普通内容默认分析传播与持续关注，只有用户明确指定商业目标时才增加询单、成交等记录。

有用户明确指定的知识库时，先读其中的 `知识库说明.md`，只读与本次复盘有关的总表、已发布正文或用户规则。仅在需要核对内容目标时读 `定位报告.md`，不以“偏离定位”代替数据证据。未建库或无文件工具时，全程在对话里交付。

## 执行

1. **提取并核对。** 读取 [复盘方法论](references/复盘方法论.md) 第一节。保留后台原指标名、人数／次数单位、统计窗口、截图时点及来源。读不清和未提供都记为缺失；真实的零单独保留。标题相似不能直接并成同一篇。
2. **建立可比样本。** 先按平台、账号、形式、分发来源、发布后时长筛选对照。窗口内增量与发布以来累计分开；原始数保留后再计算比率。没有可比历史时先做基线，不套通用“及格线”。
3. **逐篇检查。** 按方法论第二节从被看到、被打开、被看下去、被认可到持续关注排查。优先处理第一个有证据的卡点；证据不足时标“待确认”，不因上游指标缺失就跳到下游归因。数据异常不等于原因已经查明。
4. **用正文核对解释。** 有可比的高低表现篇目时，读取相应正文，检查开头承诺、读者处境、实际交付与具体证据。没有正文就保留数据描述，不声称写法导致了结果；不设“提问式开头总是更好”等固定排序。
5. **看周期和关系。** 按方法论第三、四节汇总卡点，区分话题兴趣、持续关注和明确商业目标。把重复互动、主页访问、关注、常读／回访等当不同信号；不可见的指标不推算。用户需要决定下周期复制什么，且已有明确方向与可见读者证据时，再按第四节判断高表现篇目因什么被关注，区分可试着复用的结构与题材；证据不足保留为探索，不用定位否定新方向。
6. **提出能检验的动作。** 写清改哪一处、依据哪篇、保持哪些条件、看哪个数、在什么可比窗口复查。数据不够时，补同口径截图或核对正文就是动作，不强行提出写作改法。

## 交付与保存

按需要输出以下内容，单篇分析可以合并成短段落：

- 范围：哪些篇目、哪些平台、观察截止时间，来源与缺失项。
- 事实表：关键指标、可比对照、异常环节、原因是否已核实。
- 周期判断：卡点次数及分母，支持判断的内容例子，仍待验证的解释。
- 下一步：优先做的少量动作与复查标准；没有证据时直说不能归因。

用户要求维护总表或保存报告时，按 [数据总表模板](references/数据总表模板.md) 写入指定知识库的 `数据复盘/`，或用户给定目录。新建前检查同名文件，已有篇目追加新的观察时点；只有纠正同一次录入错误才更新原观察并注明。报告可命名 `YYYYMMDD-内容数据复盘.md`；重名时询问更新范围或使用不冲突的名称，不能覆盖未授权内容。

用户校准的观察窗口、业务目标和指标定义可随其授权存入 `数据复盘/我的复盘规则.md`。自定经验值要带适用账号、形式和日期，不能变成平台规则；不允许它推翻“缺失不等于零、口径不一致不能相除”等事实约束。不要修改本技能保存个人规则。

交付前复核：分母是否同口径、是否混用了累计与增量、是否把一次成功说成规律、是否把关注直接当信任、是否把普通内容强制解释成销售漏斗。
