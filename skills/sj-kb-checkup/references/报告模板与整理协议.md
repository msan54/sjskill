# 报告模板与安全整理协议

## 一、报告写作铁律

1. **先说人话，再列证据**：开篇用一句话给出总体体检结论（最要紧的问题是什么；全绿就直说「整体健康，暂无需大动」）。
2. **严格控量（15 分钟审完）**：🔴 必须处理 和 ⚠️ 需要你拍板 合计展开不超过 15 条；超过时按对 AI 协作的影响从大到小排序，多余的写「另有 N 项同类问题，需要展开请告诉我」。
3. **只放硬路径，不写含糊描述**：每一条问题都写出完整相对路径，方便用户直接点开核对。
4. **隐私不外泄**：如果共享区抽检命中疑似手机号、密钥或敏感词，**只报文件名和命中条数**，绝不在报告里打印完整隐私明文。
5. **💡 全部折叠**：所有顺手优化项汇总成最后一行计数，不拉长正文。

## 三、用户确认后的安全整理协议

只有用户明确回复同意处理哪些条目后，才进入本阶段：

### 1. 动手前再亮一次清单
把本次将要执行的所有文件操作按动作归类列清楚：
- **先沉淀再归档**：列出源文件 → 拟提炼写入的新知识路径 → 原件移入的归档路径；
- **移动／归档**：`原路径` → `目标路径`（必须提前检查目标路径没有同名文件，冲突时自动带日期后缀或先问用户，绝不覆盖）；
- **合并文档**：保留哪一份、另一份哪些内容并入、旧件如何归档；
- **同步多端规则文件**：哪一份作为真身、同步更新哪些文件（`AGENTS.md` / `CLAUDE.md` / `GEMINI.md` / `知识库说明.md` 等）；
- **删除**：只有用户**明确授权删除**的文件才列进删除清单；未明确授权的一律改走归档。

### 2. 分批执行，步步留痕
- 先做「提炼沉淀」，再做「归档移动」，最后做「规则文件同步」。
- 绝不在用户目录里留多余的 `.bak` 或临时脚本文件。
- 如果在移动过程中发现意料之外的新冲突（例如目标文件被外部同步工具刚改过），立刻暂停并汇报，不硬覆盖。

### 3. 整理收尾汇报
- 列出全部实际完成的前后路径对照表；
- 若改动了目录名、位置或增删了 Skill，确认已把最新的目录地图同步进所有现存的 Agent 规则文件（`AGENTS.md` / `CLAUDE.md` / `GEMINI.md` 等）；
- 若检测到目录里存在 `.obsidian/` 且本次移动了 Markdown 文件，顺手提醒一句：「检测到你在用 Obsidian，如果被移动的文件有双链引用，建议在 Obsidian 里核对一下链接是否正常。」
- 建议下次体检时间（通常 1 个月后，或下次大改目录／增删 Skill 后）。
