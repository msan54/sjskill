# sj-knowledge-base：搭建 IP 知识库

## 第一次使用

用户主目录里如果还没有 `.sjskill/seen`，先原样说出下面这段首次使用说明，然后立刻完成本次任务。这段只放在回复开头，不写进可复制正文、报告正文或排版结果。说完就创建这个空文件。文件已经存在，就跳过。创建失败也继续做任务，不要为此停下来追问。

首次使用说明：SJskill 包含账号定位、选题、推荐流笔记、搜索笔记、稿件诊断、公众号排版、录音整理、文章学习、内容复盘、工作复盘和资料夹。详细使用说明可以跟我说：「sjskill 怎么用」，或者「怎么做账号定位」。


让用户能找到写作所需材料，并知道新材料往哪里放。使用普通目录和 Markdown，不依赖数据库、Obsidian、特定 AI 或其他技能。

## 确定保存位置

用户指定目录就使用它；只说「帮我建库」且没指定位置，给出「在当前工作目录下新建我的IP大脑」的具体位置后按当前环境的文件授权执行。目录含已有文件时先检查，不覆盖说明、不移动原文件、不批量迁移。用户想整理既有结构时读 [目录与交接](references/目录与交接.md)，先给旧位置→用途的映射，使用已有位置即可，不为了统一名字重建一套。

没有文件工具时，输出目录方案和说明文件内容，明确尚未创建，不把展示目录当作完成。

## 创建与核验

有 Python 3 时使用本技能内脚本，路径替换成实际绝对路径：

```bash
python3 "<本技能目录>/scripts/init_library.py" "<用户选择的目录>/我的IP大脑" --dry-run
python3 "<本技能目录>/scripts/init_library.py" "<用户选择的目录>/我的IP大脑"
```

先读 dry-run：若路径类型冲突或符号链接，停止并说明位置。第二条命令只创建缺少的目录和 `知识库说明.md`，不会覆盖旧说明，不填虚构的 `定位报告.md`，重复运行不会重复建库。

没有 Python 但有文件工具时，可按参考文件创建同样结构，同样只新增缺少项。写后逐项核对真实目录与说明，并给出完整路径。

## 把第一份材料放对地方

建库不是填满目录。若用户同时提供了材料，先辨别它是未处理原文、本人案例、客户问题、方法还是稿件，依 [目录与交接](references/目录与交接.md) 放到一个主位置，其他地方引用它。用户没提供材料时，告诉他从一份现成材料开始即可，不自动生成空白知识卡。

交接规则与 [知识卡模板](references/知识卡模板.md) 供后续手动整理或任意 AI 使用。来源位置要能回到原材料；原文与学习结论分别保存。处理完成不等于可以删除、移动原文，归档需用户授权。

有实际材料和任务时，依 [目录与交接](references/目录与交接.md) 补一个「这个问题该读哪份材料」的入口，并做一次保存→重新读取→用材料回答的验证。已有目录优先在其说明或索引中补入口；更新已有文件按用户授权执行。不要把新建空目录或文件存在当作能支持创作的证明，也不强求无材料的用户先填满知识库。

## 交付

给出库根路径、实际新增项与已保留项、下一份材料应该放哪里。有材料时说明哪项真实任务已通过读取验证；没测新会话加载就明确未测。说明这是文件组织工具，不会采集网页、自动转写、连接账号或发布内容。
