# 目录与交接

| 位置 | 保存什么 | 常见写入者 | 常见读取者 |
|---|---|---|---|
| 知识库说明.md | 此库目录用途及用户的实际保存约定 | 建库与用户 | 所有文件任务 |
| 定位报告.md | HTML 定位方案的同源文字摘要，含目标、支柱、素材与红线 | 定位任务 | 选题、写作、诊断 |
| 收件箱/ | 未整理的转写、文章、链接摘录 | 用户或已授权采集 | 录音整理、内容学习 |
| 收件箱/已处理/ | 经用户确认归档的原始材料 | 用户授权的整理任务 | 需要回查证据时 |
| 选题库/ | 用户选中的具体选题与素材状态 | 选题任务 | 写作任务 |
| 素材案例库/ | 具体事件、作品、观察，区分本人和他人 | 录音、学习、用户 | 写作与定位 |
| 客户需求库/ | 具体问题、场景、说话者与来源 | 录音、学习、用户 | 定位、选题、复盘 |
| 方法论库/ | 有适用条件的判断和操作方法 | 学习、录音、复盘 | 定位、写作与工作 |
| 待发布/ | 正在修改或准备发布的稿件与附件 | 写作、排版 | 用户、诊断、排版 |
| 已发布/ | 已由用户确认发布的稿件及发布记录 | 用户授权的登记 | 内容数据复盘 |
| 数据复盘/ | 原始指标、观察时间与分析结论 | 内容复盘 | 下一轮选题与定位 |
| 工作复盘/ | 日周事实、原因假设、下一步 | 工作复盘 | 用户的后续安排 |

只有说明文件和目录由建库脚本生成。定位、选题、知识卡、数据都应来自真实任务。

## 命名与更新

知识卡和选题用具体标题命名；稿件可用 `YYYYMMDD-平台-标题.md`。同名文件存在先查看，更新同一对象需得到授权；另一个对象使用不冲突的名字。图片放稿件同目录的 `图片附件/`，引用使用相对路径。

同一份证据只保存一份，相关结论用相对链接指向它。不要把来源材料全文复制到多个库。作者观点、用户经历和模型推测分别标明。

## 定位与选题交接

定位报告至少包括：一句话定位、目标读者及处境、内容目标、主平台和形式、内容支柱、关键词、已有素材、红线、时间条件、待验证假设。

选题卡至少包括：选题、目标读者、读者处境、核心问题、角度判断、平台、呈现形式、内容目标、素材状态、素材及来源、后续动作。素材状态只能是齐全／部分／缺失；缺证据时不能自动变为可写亲历故事。

这些是文本交接字段，不依赖专用程序。已有文件使用不同字段名但含义完整时，直接读取，不强制重命名。

## 从任务找到材料

只有材料已经存在时，才在说明或现有索引里加一个简短入口：要回答的问题、材料链接、何时使用、什么不能据此下结论。不要复制材料正文，不额外发明固定标签体系。已有目录能装下就沿用。

虚构示例：用户要写「牛仔裤膝盖破了值不值得修」，已有一组修补照片。入口可写：「判断这份修补的外观效果 → 素材案例库/膝盖修补.md；可展示修补前后，未做耐穿测试，不能证明耐用年限。」只写「修衣素材」不能帮助下一次任务判断该不该用。

保存后按原路径重新打开文件，再用它回答用户的具体问题，指出哪一句来自材料、哪项仍未知。能开文件但回答引用错案例，仍未通过。若当前环境支持隔离的新会话，并且用户授权使用这些材料，可只给入口与任务验证能否找回；否则记录「本会话已重新读取，新会话加载未测」，不伪造端到端验证。用户只建空库时，交付结构即可，材料可用性留待首次实际任务验证。
