# 知识库说明

这份说明告诉你和 AI：每样东西放哪、谁会来读。东西放哪，以这份说明为准；你改了存放习惯，就改这里，不在别处另写一份。

## 目录结构

```
我的知识库/
├── CLAUDE.md 或 AGENTS.md   AI 每次开工先读的协作协议（只放规矩）
├── 知识库说明.md             就是这份
├── 说明书/                   我是谁、我的客户、我的风格、我的内容标准、我的对标账号；做过账号定位的，核心定位卡也放这里
├── 产品库/                   产品说明书、买点清单、常见异议（没有产品就先空着）
├── 素材库/                   真实案例、客户原话、金句
├── 方法论/                   你自己总结出来的判断和做法；一开始是空的
├── 输入/                     原档：别删，留着能回溯
│   ├── 录音/待处理/          新的录音转写丢这里
│   ├── 录音/已处理/          整理完的挪到这里
│   ├── 课程学习/             上课的资料和笔记
│   └── 内容学习/             想学的文章、口播稿
├── 选题库/                   一条选题一个文件，标好优先级和素材状态
├── 待发布/                   写好、还没发的稿子
└── 已发布/                   发出去的稿子
```

数据复盘、工作复盘这些目录，第一次用到对应技能时再建。

## 东西往哪放

| 手上的东西 | 放哪 | 谁会来读 |
|---|---|---|
| 录音转写、逐字稿 | `输入/录音/待处理/` | 整理录音的技能 |
| 想学的文章 | `输入/内容学习/` | 学文章的技能 |
| 自己的一件真事、一个案例 | `素材库/真实案例.md` | 写笔记、写公众号 |
| 客户或读者说过的原话 | `素材库/客户原话.md` | 选题、写作、定位 |
| 自己总结出的一条做法 | `方法论/`，一个问题一个文件 | 写作、诊断 |
| 想写的选题 | `选题库/`，文件名就是选题标题 | 写作 |
| 写好的稿子 | `待发布/YYYYMMDD-平台-关键词-v1.md` | 诊断、排版 |
| 发出去的稿子 | 从 `待发布/` 移到 `已发布/` | 内容复盘 |

## 三条规矩

1. **原档和方法分开**：`输入/` 里的原档留着能回溯，不直接拿来当结论；整理出来的判断放进说明书、素材库或方法论。
2. **同一件事只放一处**：会变的东西（价格、规则、数字）只写在一个文件里，别处引用，不复制。
3. **从用到的地方长**：不追条数，用到一样整理一样；一个文件说不清「谁在什么时候用它」，就先留在 `输入/`。
