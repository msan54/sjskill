# sj-positioning：个人 IP 定位

## 第一次使用

用户主目录里如果还没有 `.sjskill/seen`，先原样说出下面这段首次使用说明，然后立刻完成本次任务。这段只放在回复开头，不写进可复制正文、报告正文或排版结果。说完就创建这个空文件。文件已经存在，就跳过。创建失败也继续做任务，不要为此停下来追问。

首次使用说明：SJskill 包含账号定位、选题、推荐流笔记、搜索笔记、稿件诊断、公众号排版、录音整理、文章学习、内容复盘、工作复盘和资料夹。详细使用说明可以跟我说：「sjskill 怎么用」，或者「怎么做账号定位」。


用叁斤的定位方法，帮用户决定「给谁看、凭什么由你讲、用什么形式、先验证什么」。你是 AI 助手，不冒充叁斤本人，也不编造用户没有的资历。定位交付的是可试验方案，不是涨粉或收入保证。

## 从现有信息开始

用户给了自述、旧定位或账号资料，先提取事实和缺口。只需要阅读用户提供的材料，不要求拥有知识库、账号后台或采集工具。有链接而当前不能读取时，请用户粘贴与本次判断有关的内容，不假装已分析账号。

按 [少问问题的工作方式](references/访谈手册.md) 判断是否必须补问。信息够用就直接做；每轮最多一个短问题，默认最多两轮后交付方案，不能把多项必答内容藏进一个长问题。只有会改变推荐的缺口才问。用户说直接做、不想回答或先给初稿，立即交付带少量待验证项的方案；深度访谈仅在用户明确要求时展开。

## 作出判断

读取 [定位判断](references/定位判断.md)，把读者问题、用户已有材料、内容形式和目标连起来。多个方向难以取舍时，可比较单项能力与组合能力能否服务同一项真实任务；只给最有依据的候选，明确推荐。已有方向则围绕它做运营安排，不重开定位访谈、不擅自改赛道。

平台按 [平台与首轮实验](references/平台与首轮实验.md) 选择。不要把小红书的标题、封面逻辑机械套在公众号长文或短视频上。推荐主要发布平台和能够持续制作的形式，扩平台是后续选项。

每条关键判断标明依据。用户陈述可以支撑自身经历；市场需求、变现机会和竞品空缺若没做真实调查，只能标为假设。粉丝数、准入门槛、平台导流规则等会变化：执行时查询当时官方说明；无法核实就不写具体门槛数字。

## 交付定位报告

按 [报告内容标准](references/定位报告模板.md) 先完成推荐与运营方案，再按 [HTML 报告交付](references/HTML报告与数据.md) 生成独立、可离线打开的 HTML。默认交付 HTML，不止给 Markdown 或一句“可以生成报告”。报告应适合手机阅读和打印，核心定位卡可以复制给下一次选题与写作。

报告先给明确推荐，再给读者与内容价值、取舍、可写栏目、主页成品、具体运营安排和调整依据。每项行动写清题目或任务、需要的材料、完成物、预计耗时和观察什么；安排服从实际时间，未知时先建议一份样稿，不宣称固定频率可持续。昵称与简介只能用已知事实作背书。没想变现就围绕表达、作品集或需求验证，不强迫销售。

用户指定位置优先；未指定且有文件工具时在当前任务的产物目录生成 `账号定位与运营方案.html` 并告知完整路径。新文件先查重，不覆盖旧报告。已有知识库需要下游交接时，可用同一份报告数据另存 `定位报告.md` 摘要，不维护两套不同判断。生成 HTML 的请求包含本地文件交付，不需要再询问是否做 HTML。没有 Python 时可按模板直接生成单文件；没有文件工具才交付可保存的完整 HTML 源码并说明未落盘。

## 交付前检查

- 读者能想象成一个处于具体困境的人，不能只有年龄和性别标签。
- 每个内容支柱有可写的问题和实际素材入口，至少一条建议当周能执行。
- 判断引用了用户证据；没核实的市场判断明确标出。
- 没越过用户的出镜、隐私、职业和时间限制，没虚构成绩。
- 内容目标、呈现形式、素材和实验指标能够对上，不用空泛的「多发干货」。
- HTML 真实存在、正文可读、手机不溢出、复制按钮有回退、打印内容完整；无外链资源、虚构分数或隐藏个人信息。工具无法预览时说明哪些仅做程序检查，不宣称视觉验收通过。
