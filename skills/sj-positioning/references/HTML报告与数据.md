# HTML 报告与同源数据

先按 [定位报告模板](定位报告模板.md) 作出推荐和首轮安排，再把结论写入一份 UTF-8 JSON。用 [生成脚本](../scripts/render_report.py) 和 [离线模板](../assets/report.html) 生成 HTML；需要下游交接时同时导出 Markdown 核心卡。两份交付都由同一份数据生成，不分别撰写互相矛盾的定位。

不要把填 JSON 变成新的用户问卷。已知事实直接用；非决定性缺口放待验证项；预算未知时先交一份样稿安排。没有条目的列表用 `[]`，没有事实就明确说明暂定依据，不填虚构资历或市场数据。

## 生成与交付

使用 Python 3.9 或更新版本，只用标准库，无须安装依赖。以下命令从本技能目录执行，输入和输出路径也可换成用户指定的绝对路径：

```bash
python3 -B "scripts/render_report.py" "input.json" "账号定位与运营方案.html"
python3 -B "scripts/render_report.py" "input.json" "账号定位与运营方案.html" --markdown "定位报告.md"
```

这两行是两个用法，择一执行；脚本不会覆盖已经生成的报告。目标父目录须已存在；助手根据当前任务选用产物目录并先查重，不在用户未知的位置建库。输入与输出不能同名；HTML 与 Markdown 不能共用路径；输出及其父目录不能是软链接。需要用系统临时目录时，使用其真实路径，例如 macOS 的 `/private/tmp`。

成功返回退出码 `0` 和实际产物路径；失败返回非零及原因。所有字段、预算与输出路径在写入前检查，已有文件保持原样。磁盘写入失败时只清理本次独占创建且未被替换的文件，不删除原有文件。脚本不会发布、联网、读取账号或抓取链接。

使用 [合成示例数据](../assets/example-report.json) 可预览完整效果：

```bash
python3 -B "scripts/render_report.py" "assets/example-report.json" "虚构定位示例.html" --markdown "虚构定位示例.md"
```

示例是「修衣六年、五组照片、不出镜、每周三小时、小红书面向附近居民」的虚构小林，包含两周安排。它只供教学和测试，不能改个名字就充当真实用户的经历、素材或运营证据。实际输出前替换成当前用户资料，并保留真实缺口。

## 固定报告署名

HTML 页尾保留「这是叁斤给出的账号定位方案」「叁斤｜公众号：叁斤｜微信：Msan54」与「由叁斤提供的 SJskill 基于当前资料生成」。署名在手机阅读和打印样式中均保留；不需要向用户收集额外字段，也不表示叁斤逐份审核过报告。

导出的 Markdown 与可复制核心卡继续使用相同内容，末尾附独立「报告署名」区，并注明它不属于用户身份、主页文案或可用创作素材。把核心卡交给下游选题、写作助手时，这一节只作套件来源说明，不能写进用户的简介、故事、事实或待发布正文。署名不得加入 JSON 的 `homepage.bio`、定位、证据或素材字段。

## 数据字段

根对象使用下表字段；除 `report_date`、`case_notice` 可省略外，其余均需提供。文字字段是非空字符串，允许换行；列表内容不足时减少条目，不凑规定数量。脚本拒绝未知字段，避免拼错后悄悄丢掉内容。

| 字段 | 类型与用途 |
|---|---|
| `report_title` | 报告标题，先让读者看见推荐方向。 |
| `subject` | 用户自称或当前方案名称，不补造身份。 |
| `report_date` | 可选，`YYYY-MM-DD` 格式的实际报告日期；省略时显示未提供。 |
| `case_notice` | 可选，合成测试必须明确写「虚构教学案例」及其范围；真实报告不带测试说明。 |
| `recommendation` | 推荐、理由、第一步、取舍与判断依据。 |
| `positioning` | 读者、问题、价值、依据、平台、形式和目标。 |
| `evidence` | 已知事实与来源列表，和待验证假设分开。 |
| `pillars` | 内容栏目列表，含实际题目与材料状态。 |
| `homepage` | 昵称候选、简介和头像／封面方向。 |
| `resources` | 时间预算、素材及缺口。 |
| `stages` | 首轮安排；已知周预算时每项代表一个执行周，不要求四周。 |
| `review` | 可见反馈如何影响下一轮动作。 |
| `unknowns` | 待确认事项、对方案的影响、最小核对动作。 |

### 推荐与定位

`recommendation` 包含：

- `direction`：明确推荐做什么。
- `reason`：为什么与用户材料、目标和限制相符。
- `first_step`：今天可以开始的具体动作及材料。
- `tradeoffs`：文字列表，本轮暂不投入什么及原因。
- `judgments`：对象列表，每项为 `label`、`judgment`、`basis`。可用于可替代性、需求证据、到目标的步骤、执行匹配等判断；这些是有理由的文字，不是雷达评分。

`positioning` 包含以下文字字段：

| 字段 | 填什么 |
|---|---|
| `one_liner` | 一句话定位，连接读者处境、内容价值与本人依据。 |
| `reader` | 具体读者在什么处境下需要内容。 |
| `reader_problem` | 要解决的核心问题。 |
| `value` | 看完能多做什么判断或动作。 |
| `basis` | 本人经历、作品或材料依据；不足时写清暂定。 |
| `goal` | 用户希望账号帮助达成的结果；不编数量保证。 |
| `platform` | 主平台与选择依据，已有明确选择时沿用。 |
| `format` | 与素材、出镜边界及制作成本匹配的形式。 |
| `voice` | 说话与展示方式，用具体动作描述。 |

另有两个文字列表：`keywords` 写搜索表达、意图及来源状态；`boundaries` 写实际隐私与表达边界。未采集的关键词标候选，不能伪装成高频词。

### 证据、栏目与主页

- `evidence` 每项含 `fact`、`source`、`impact`：事实、材料出处、对推荐的影响。来源只保存与判断有关的说明，不带凭据、内部访问地址或未授权身份信息。
- `pillars` 每项含 `name`、`reader_question`、`purpose`、`format`、`topics`。前四项为文字；`topics` 至少一项，每题含 `title`、`materials`、`status`。`status` 只能是「可制作」或「待准备」；标「可制作」前确认材料足够，公开许可另在素材中注明。
- `homepage` 含 `names`（非空文字列表）、`bio`、`avatar`、`cover`（文字）。简介是可用成品，不放待填地址、虚构成绩或技能作者广告。没有服务区域或联系方式时，先不写这部分。

### 时间、素材与首轮安排

`resources` 包含：

- `weekly_minutes`：每周可投入分钟数，为非负整数或 `null`。用户说三小时应写 `180`；没说则写 `null`，不能从职业或身份推算。
- `notes`：预算来源、制作条件和估算限制。
- `materials`：对象列表，每项含 `name`、`ownership`、`public_scope`，说明材料名称、归属和公开范围。没有实际看到的图片不能写成已核验。
- `gaps`：具体素材缺口的文字列表。

`stages` 每项含 `name`、`focus`、`tasks`、`observe`、`decision`。除 `tasks` 外均为文字。`observe` 说明何时观察什么，`decision` 说明什么反馈导致什么调整；未发布、没数据和零反馈不能混作同一状态。

`tasks` 至少一项，每项包含：

| 字段 | 填什么 |
|---|---|
| `title` | 可直接开始的任务名，关联具体题目。 |
| `materials` | 用哪组照片、哪份记录或什么可获得材料。 |
| `action` | 具体制作、核对或记录动作。 |
| `deliverable` | 可审阅的文件、样稿、清单或记录。 |
| `estimated_minutes` | 预计耗时，正整数分钟；时间无法估计时用 `null`。 |

已知周预算时，一阶段按一周计算，所有任务必须有预计耗时，合计不得超过 `weekly_minutes`。准备、制作、核对与反馈记录都应计入；等待反馈的自然天数不算制作工时。生成器会计算总耗时与尚未分配的时间；已经作为任务列出的机动时间也计入合计，不能重复计算。

每周时间未知时，只安排一个阶段，围绕一份样稿写必要动作；可以给标明预计的耗时，也可以保留 `null` 待实测，不推导固定发布频率。只有时间预算确为零时，才可用空 `stages` 表示本周暂不安排制作。生成器核算数字，不能替代助手检查文字里有没有旧预算、额外任务或相互冲突的时间承诺。

### 反馈与待验证

- `review` 每项含 `signal`、`interpretation`、`action`：实际会观察的信号、能够说明和不能说明什么、下一步怎么改。没有数据时保留尚不能判断，不编达标阈值。
- `unknowns` 每项含 `item`、`impact`、`check`：未知事项、为何影响方案、最小核对动作。不把它输出成必须一次答完的新问卷。

## 安全与阅读验证

所有数据只作为文字显示，统一进行 HTML 转义；固定脚本读取已转义文本框，不把 JSON 拼进 JavaScript，也不把数据当 HTML 执行。模板没有外部字体、图片、脚本或网络请求，来源链接作为文字保留。Markdown 核心卡也转义用户字段中的 HTML 和 Markdown 语法。

报告包括宽窄屏样式、打印样式、证据折叠和核心卡复制。打印前脚本展开证据，结束后恢复原状态；脚本禁用时先手动展开证据再打印。复制优先使用浏览器剪贴板，失败则选中文本并尝试复制，再失败会提示手动复制。

生成后实际打开 HTML，检查首屏推荐、手机横向溢出、证据展开、复制与打印。程序通过只代表生成与字段检查通过，不能代替界面验收；无法预览时明确说明。报告也不代表运营效果已经验证。

## 没有 Python 或文件工具时

有文件工具但无 Python：按 [离线模板](../assets/report.html) 的结构直接生成单文件 HTML，把所有用户文字转义为文本，不保留 `@@...@@` 标记；手动核对各阶段工时。保留固定复制脚本及其回退、页尾报告署名和核心卡中的独立署名区，不把用户数据插入脚本。

没有文件工具：交付可以保存为 `.html` 的完整代码，说明未落盘。此时不能声称“报告已生成在某路径”，也不以纯 Markdown 代替用户要的 HTML。
