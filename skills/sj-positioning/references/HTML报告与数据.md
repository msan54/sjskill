# HTML 报告与数据

按 [定位报告模板](定位报告模板.md) 想清楚方案后，把内容写进一份 UTF-8 JSON，再用 [生成脚本](../scripts/render_report.py) 套 [离线模板](../assets/report.html) 生成 HTML。HTML 和可复制的核心定位卡出自同一份数据，不会互相矛盾。

## 生成命令

Python 3.9 或更新版本，只用标准库。命令在本技能目录执行，输入输出也可以换成用户指定的绝对路径：

```bash
python3 -B "scripts/render_report.py" "input.json" "账号定位与运营方案.html"
python3 -B "scripts/render_report.py" "input.json" "账号定位与运营方案.html" --markdown "定位报告.md"
```

两行择一：第二行多导出一份 Markdown 核心定位卡，给知识库和后续写作用。脚本不覆盖已有文件，输出的父目录要先存在，输出路径不能是软链接。成功返回 `0` 并打印文件路径；失败返回非零并说明哪个字段有问题，不会留下半份报告。脚本不联网、不读账号、不抓链接。

看完整效果可以用随技能附带的虚构示例：

```bash
python3 -B "scripts/render_report.py" "assets/example-report.json" "示例定位方案.html"
```

示例里的「小鱼」是为演示方案写法虚构的人物，不能改个名字就当成真实用户的方案。

## 数据字段

文字字段都是非空字符串，可以换行；列表里的每一项也是非空文字。缺字段、多出不认识的字段都会报错，免得内容被悄悄丢掉。

| 字段 | 写什么 |
|---|---|
| `report_title` | 报告标题，让人一眼看出推荐方向 |
| `subject` | 用户的称呼 |
| `report_date` | 可选，`YYYY-MM-DD` |
| `status` | `完整方案` 或 `初稿` |
| `case_notice` | 可选，只给虚构示例用，真实报告不写 |
| `assumptions` | 可选的文字列表；`status` 是 `初稿` 时必填：哪几处是推测的、补上什么会改方案 |
| `verdict` | 叁斤式总判断，3—5 句 |
| `core` | 核心定位卡，见下 |
| `audience` | 目标受众画像，见下 |
| `directions` | 内容方向列表，见下 |
| `style_guide` | IP 风格指南，见下 |
| `growth` | 成长路径，至少 3 个阶段 |
| `monetization` | 变现策略，见下 |
| `launch` | 前 30 天执行，见下 |
| `score` | 叁斤评分，见下 |
| `market_keywords` | 市场验证要搜的 3—5 个核心关键词 |

### core：核心定位卡

`one_liner` 一句话定位；`value` 核心价值；`audience` 目标用户；`persona` 关键人设；`format` 内容类型；`style` 核心风格；`platform` 主平台＋为什么；`goal` 账号目标（变现方式或想要的结果）；`red_lines` 文字列表，用户说过的红线，没有就给空列表。

HTML 的「价值 × 用户 × 人设 × 类型 × 风格」五张卡和可复制的核心卡，都直接读这五个字段。

### audience：目标受众画像

`basic` 基本信息；`economy` 经济水平；`life` 生活状态；`inner` 内心世界；`attention` 她刷到什么会停下来、想看什么、用什么语气跟她说话。

### directions：内容方向

完整方案 3—5 个方向，每个方向至少 2 个选题；初稿可以只给 1 个方向、1 个选题。每项：

- `name`：方向名。
- `role`：`引流款`、`信任款` 或 `人设款`。
- `share`：占比建议，比如 `40%`。
- `why`：为什么做这个方向。
- `topics`：能直接开写的选题列表。

### style_guide：IP 风格指南

`names` 昵称候选 2—3 个（第一个是首选）；`name_note` 首选理由和天花板提醒；`bio` 可直接复制的四段式简介，用换行分段；`avatar` 头像建议；`cover` 封面与主页建议；`voice_rules` 说话规矩，至少 3 条。

简介只写用户给过的事实，不放叁斤的署名和联系方式。

### growth：成长路径

至少 3 项，每项 `stage`（阶段名，比如「快速起号期（0—1 万粉）」）和 `plan`（这个阶段他具体做什么、节奏多快）。

### monetization：变现策略

`short_term` 起号期的铺垫；`long_term` 主路径和备选路径，平台门槛注明以官方后台为准；`warnings` 变现红线列表，至少 1 条。

### launch：前 30 天

`week1` 第 1 周动作列表；`weeks2_4` 第 2—4 周动作列表；`benchmark` 找对标的标准列表；`reminder` 防完美主义的一句话。三个列表都至少 1 项。

### score：叁斤评分

`items` 固定 4 项，按顺序是门槛、供需、离钱距离、执行匹配。每项 `name`、`level`、`reason`、`line`：

- `level` 只能是 `高`、`中偏高`、`中`、`中偏低`、`低`——用档位不用分数。
- `reason` 带证据的理由，执行匹配必须引用用户原话。
- `line` 一句直话。

`verdict` 总判词：能不能干＋最大的坑＋出口。

## 生成后检查

实际打开 HTML 看一遍：首屏的总判断、五张公式卡、内容方向和选题、简介、叁斤评分、市场验证都在；手机宽度下不横向滚动；「复制核心定位卡」能用，复制失败时会自动选中文本；打印时内容完整。工具没法预览时，说明只做了程序检查。

## 没有 Python 或文件工具时

有文件工具但没有 Python：照 [离线模板](../assets/report.html) 的结构直接写单文件 HTML，把所有用户文字当普通文本转义，不留 `@@` 标记，保留复制脚本和页脚署名。

没有文件工具：在对话里交付完整方案，并说明没有生成文件，不说「报告已生成在某路径」。
