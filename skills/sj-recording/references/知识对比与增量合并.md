# 知识对比、全面沉淀与新建分类规则

适用于要把录音里的东西写进知识库的时候。A2、A3 必读；A1、B 有东西要沉淀进知识库时读。

## 一、先认用户的库，再找旧内容

不要假设用户的目录名字。动笔比对之前，先做两件事：

1. **读协作说明**：按顺序检查知识库根目录（及当前子分区）下是否存在 `AGENTS.md`、`CLAUDE.md`、`GEMINI.md`、`.cursor/rules/`、`.cursorrules`、`知识库说明.md`、`README.md`，读清目录分工、命名规范、卡片模板、共享区／私有区边界和脱敏要求。
2. **扫真实目录树**：列出当前知识库的一、二级文件夹（避开 `.git`、`.obsidian`、`node_modules` 和归档目录），确认每个类别实际住在哪里。

先写完整理稿、列好候选沉淀清单，再去查旧库。不边提取边写入。

每个候选至少记：

- 标题和沉淀类型（案例／客户原话／金句／方法论与 SOP／选题／新主题观点／课程知识）
- 核心结论或事件
- 人物、对象和适用场景
- 数据、原句和来源锚点（文件名＋时间戳）
- 3—8 个检索词：主题词、同义词、人名、案例名或方法名
- 拟去向：已有目录／已有文件，或 `【建议新建分类】父目录/新分类名/`

## 二、去哪查、怎么查

按用户实际目录顺序查（没有协作说明时参考括号内默认名）：

1. 录音已处理目录（如 `输入/录音/已处理/`）里同一个人、同一主题的旧整理稿
2. 案例／项目素材目录或文件（如 `素材库/项目案例/`、`素材库/真实案例.md`）
3. 客户问题／客户原话目录或文件（如 `素材库/客户问题/`、`素材库/客户原话.md`）
4. 金句库或金句目录（如 `素材库/金句库.md`、`金句/`、`个人/金句/`）
5. 方法论／业务标准／SOP 目录（如 `方法论/`、`业务标准/`、`知识资产/`）
6. 课程学习目录（如 `输入/课程学习/`）里同一位老师、同一套知识的资料
7. 选题库（如 `选题库/` 或各账号下的 `选题库/`）里同一个角度的选题
8. 个人思考／专题目录（如 `个人/`、`观点/`、`创业思路/` 等已有主题夹）

查的要求：

- 先用原词搜，再用同义词、旧叫法和场景词扩大范围。
- 只搜到文件名不算查过，要打开最相关的文件，核对意思、来源、适用场景和版本。
- 每个判断都写出旧内容在哪；没找到的，写清查过哪些地方。
- 不能因为措辞像就判重复，也不能因为措辞不同就判全新。

## 三、六类差异判定

| 类型 | 怎么判断 | 怎么处理 |
|---|---|---|
| 完全重复 | 核心结论、事件、前因后果和适用场景都一样 | 不写，只在整理稿里记下已有位置 |
| 换了说法的重复 | 换了表达或听众，说的还是同一件事 | 补上这次的来源；没有新信息就不改正文 |
| 新场景、新证据 | 核心不变，多了对象、反馈、数据、结果或案例 | 追加到原来那一条的证据或适用场景里 |
| 升级或修正 | 改了步骤、边界、判断标准或旧结论 | 更新成现在有效的版本，旧说法记进版本变化 |
| 冲突待确认 | 新旧说法不能同时成立，证据又不够裁决 | 两说都留，标出各自的来源和待验证的问题 |
| 全新内容 | 知识库里没有同义的知识或同一个案例 | 写入已有对应分类，或按第五节走「新建分类」流程 |

先后顺序：完全重复和换了说法的，先不新增；近似的，先补场景和证据；只有说的确实是另一件事，才新建。

## 四、专项去重与入库规则

### 1. 案例与项目素材
按「事件＋人物＋前因后果」判重，不看文字相似度：
- 同一个案例讲给不同的人听，还是一条案例；新听众的反应、追问和异议补成「受众反馈」。
- 同一件事后来有了新结果、新数据或新教训，更新原来那条的结果。
- 如果用户库里已经有一事一卡的素材卡格式（例如项目案例卡、一线经验卡、岗位信息卡），**直接按用户已有的卡片栏目和模板写**，材料里没有的栏写「待补」，绝不替用户编造数字。

### 2. 客户原话与客户问题
- 按「担心的是不是同一件事」判重，不看措辞完全相同。
- 必须留真实原句、客户类型、日期和来源；AI 改写的、用户转述的、客户本人说的原句分开放。
- 若用户库里采用「一问一卡」记录客户问题，同一个问题直接在旧卡上累加出现次数、追加原话和来源，不新建平行卡。

### 3. 金句沉淀
- **什么样的句子进金句库**：一针见血的洞察、生动好记的比喻、打破误区的判断、自带画面和情绪的口语原句（空洞鸡汤和泛泛总结不收）。
- **每条金句固定记四项**：原句（一字不改、加引号）、谁说的（用户本人／对话者／讲师）、语境或适用场景、来源（录音整理稿或原稿名＋时间戳）。
- **怎么存**：用户库里已有金句库文件或金句目录的，查重后直接追加或建卡；没有的，在确认清单里提议新建（例如个人知识库放 `素材库/金句库.md`，多分区企业库放个人区的 `金句库.md` 或 `金句/`）。

### 4. 同一位老师多次课程迭代
按「老师＋他那套知识」归并，分三层：原稿（只读证据）→ 单场整理稿（本次讲了什么）→ 主知识文档（当前最完整有效版本）。
- 小范围案例、解释、边界补充 → 升小版本（如 v1.1）；核心框架或步骤变化 → 升大版本（如 v2.0），在「版本变化记录」留痕。
- 每个知识点挂双链接：`📌 来源`（课程名＋日期＋时间戳）和 `🎯 应用`（用户真实使用场景，没有写「待补」）。

## 五、动态新建分类文件夹规则（已有直入，无类可建）

录音里常常会冒出对用户极有价值、但知识库现有目录里**还没专门设类**的内容——例如聊完一次复盘产生了一批「创业思路」「团队管理」「股权合伙」「行业趋势判断」观点。处理原则如下：

1. **先判断有没有现成归属**：先查用户现有的一、二级目录。能自然放进已有目录（比如已有金句库、方法论、业务标准、案例库）的，**绝不另起炉灶**。
2. **满足以下三条才提议新建分类**：
   - 内容对用户未来做决策、写内容或带团队有**长期复用价值**（不是一次性碎事）；
   - 放进任何现有文件夹都会显别扭，或者放进去以后很难再找出来；
   - 这个主题以后很可能还会继续长出新内容（如创业思路、带团队心得、某个长期研究主题）。
3. **新分类建在哪一层**：
   - 遵守用户协作说明里的顶层分区。比如多分区库里，个人感悟、创业思路、外学方法建在「个人区」下；团队通用业务标准建在「公司经营／业务标准」下；对外内容素材建在「运营／素材」下。
   - 命名清晰直白，延续用户现有文件夹的命名风格（用短中文名，不造晦涩术语，层级不超过 3 级）。
4. **必须先列进确认清单再建**：
   - 在写入计划表里清楚标出：`【建议新建分类】目标父目录/新分类名/`，写明「为什么要建这个类」和「本次拟放入的 1—N 条内容」。
   - 用户确认后，再创建文件夹并写入规范化的观点／知识文档（一条一个文件或按主题聚合，均包含核心观点、背景与依据、适用边界、`📌 来源`、`🎯 应用`）。
5. **收尾提醒同步规则**：建完新分类后，提醒用户在协作说明（`AGENTS.md` / `CLAUDE.md` / `GEMINI.md` / `知识库说明.md` 等）的目录表里补上一行，避免下次 AI 找不到这个新文件夹。

## 六、多分区与团队共享区的安全脱敏规则

当协作说明或目录结构显示这是一个**区分了共享区与私有区的知识库**（例如「运营共享／公司经营／个人」）：

- **共享区写入前必查脱敏**：报价底线、成本、利润、提成、合同条款、客户对接人手机号与微信号、求职者或员工个人隐私信息，**绝不直接写进共享区**。若原文含此类信息，写入共享区版本时必须脱敏，原样记录留在私有区整理稿。
- **尊重待审核缓冲区**：若共享区设有 `待审核/` 目录，新整理的素材卡先存入 `待审核/`，由管理员审核后再移入正式素材库，不越权直写只读区。
- **外部学来的与正式标准隔离**：从外部课程、访谈、分享学到的方法，在用户明确采纳成自己或公司的做法之前，留在个人学习／方法论区并标「待验证」，不直接写进正式业务标准（SOP）。

## 七、写入前先列沉淀计划

把「已有位置更新」和「建议新建分类」放进同一张确认表：

| 候选内容 | 类型 | 差异判定 | 目标位置（已有路径 或 `【建议新建分类】路径`） | 拟执行动作 | 备注（如脱敏／待审核） |
|---|---|---|---|---|---|

用户确认该表后，计划内的新增、建夹和增量更新一次做完，不再一条一问。只有遇到以下五种情况才暂停追问：

- 要用新结论替换旧结论，但替换关系不明确；
- 新旧知识冲突较大，需要用户拍板；
- 写到一半发现需要额外新建未确认的分类目录；
- 涉及共享区敏感信息不确定能否公开；
- 实际修改范围超出了确认过的计划。

不删除旧知识。需要淘汰的，在主文档标注历史状态，或待用户确认后移入归档目录。
