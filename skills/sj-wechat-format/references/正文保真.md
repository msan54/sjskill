# 正文保真与交付边界

正常运行 [render.py](../scripts/render.py) 即执行 [fidelity.py](../scripts/fidelity.py) 的核对，无第三方依赖。任一核对失败都发生在创建输出目录、写入或覆盖 HTML 之前；原稿和标注副本始终只读。

## 原稿→临时标注副本

用了副本就必须传 `--as "原稿.md"`。脚本比较标题、正文逐行内容、代码、每次出现的链接文字与目标、图片引用与替代文字、各项的顺序。不会去掉全部标点或全部空格再比对。

允许的格式变化：成对的 `**加粗**`、`==重点==`、段首的分节标题标记、引用标记和无序列表标记，以及正文空行和行首末空白。标题文字可以加粗；文章开头的一级标题仍是文章标题，不可把普通首段升级后当成从正文消失也没关系。编号、正文行内空格、代码缩进、字词、标点和链接目标必须保留。已有 front matter 作为元数据不进正文，但原稿和副本中的元数据必须一致。

例如「不能直接照抄」变为 `==不能直接照抄==` 可通过；变为「能直接照抄」会失败。把图片从「前文」与「后文」之间移到段末，也会失败。

图片支持本地路径的百分号解码和 Obsidian 显示宽度标记，但不会把不同的文件引用当成只改格式。核验依据是本次运行能读取的图片，不能证明图片文件在运行之前未被其他人修改。

## 输入稿→HTML

从实际 HTML 的 DOM 读取 `<title>`、正文段落、代码文字、文末参考链接和内嵌图片，再与稿件比较；这不是浏览器计算样式后的可见性检查：

- 首个 `# 标题` 核对到 `<title>`，不重复进入正文。
- 正文外链保留链接文字，文末逐条保留「文字：目标」，重复链接也保留，不能错配目标。
- 图片按实际字节的 SHA-256、替代文字、出现顺序及前后文字位置核对，不只是数 `<img>` 个数。
- 无序列表只加入约定的圆点；代码中的 Markdown、图片写法和链接保持字面文字。

脚本分别输出正文保真结果与 HTML 标签兼容结果。直接渲染原稿时，第一道显示「不适用」，只证明该输入稿与 HTML 相符。不能把省略 `--as` 当作处理失败的办法，也不能只凭退出码或「兼容通过」宣称原稿保真。

## 表格及其他不能自动校验的输入

当前不解析表格，也不声称能证明手工列表与表格等价。检测到 Markdown 表格分隔行或 HTML 表格时停止，并指出正文行号。即使手工转换后的文字总数相等，也不能证明「甲的收入」没有串到「乙」那行；禁止删竖线、冒号或列名后用拼接字符串判定相同。

需要人工转换时：保留原表，按表号、行号、列名逐格记录到列表，对照每个空单元格、单位、图片及链接，不合并多行列头或推测合并单元格的含义。让用户审阅转换稿；只有用户确认它作为新的输入稿后，才独立渲染该稿，并在交付说明「原表格→列表经过人工处理，自动等价校验未完成；本次通过的范围是新列表稿→HTML」。不要对原表格报告「保真全通过」。复杂表格无法确认关系时保留原信息、停止转换。

远程图片换成本地图片同样涉及引用变化：保留原网址和来源核对记录，说明远程图片一致性未经本脚本验证，经用户确认的新稿再作为输入；脚本不访问网络，也不自动证明远程内容未变化。

轻量语法以外的复杂嵌套、公式、脚注等不承诺排版语义。遇到核对失败应报告不支持的位置或修复渲染问题，不靠丢字、换词、删除特殊符号或跳过核对凑通过。代码块开头允许三个反引号及简单语言名，结束只能是三个反引号；缺失结束围栏、结束围栏尾随文字会停止。链接目标有未编码括号时会停止，不截断 URL 后报告成功；已有百分号编码的 URL 可直接使用。

## 交付应带什么

给出真实 HTML 路径、两道保真结果、兼容自检结果、图片和链接数量及明确限制。保真仅覆盖本次生成的本地文件；之后手工编辑 HTML 需要重新核对。微信公众号后台的剪贴板过滤、图片上传和手机预览仍须实际操作后检查，本地生成成功不代表已经发布或后台兼容已验证。
