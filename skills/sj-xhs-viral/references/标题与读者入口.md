# 标题与读者入口

标题的工作是让合适的读者认出：这篇与我正在想的事有关。正文应回应这个期待。吸引力可以来自事件、矛盾、感受、实用答案，不必都靠反转。

## 挑说话位置

以下均为虚构教学例句，只演示句子站位，不代表任何人的实际经历。

| 入口 | 教学例句 | 使用条件 |
|---|---|---|
| 直接说出困境 | 「准备了很久，还是没交出第一版」 | 正文确实讨论准备与交付 |
| 读者可能说的那句话 | 「我不是不想做，我是不知道从哪开始」 | 是拟写句，不能加引号冒充客户原话 |
| 一个具体选择 | 「把计划表合上，先发出去一小段」 | 正文有理由与边界，不能只喊行动 |
| 具体人物的事 | 「她把练习本带来了，却一直不敢翻开」 | 人物与动作来自真实材料；这是例句，不得套给用户 |
| 一个有限判断 | 「计划写得越细，为什么越难开始」 | 正文能解释什么时候成立，不宣称普遍规律 |

人物故事本身有吸引力时可用作者作为主语；不用「不能出现我」这种机械规则。标题里读者不熟悉的项目名、产品简称、内部术语会增加理解成本，判断它们是不是必要信息。

## 逐个检查标题里的前提

拿到标题后问：

1. 读者是否遇得到这里的困境或选择？仅写「自媒体人」只是身份，没有说明他在烦什么。
2. 标题让人期待得到什么？是答案、过程、情绪理解，还是看见一个结果？
3. 正文的材料能支持承诺吗？写「只要」「永远」「人人都」时尤其检查适用条件。
4. 抽掉感叹词后还有明确意思吗？没有就先换信息，不继续加语气。

不为了标题锐利删去关键限定。正文只讨论某种工作场景，就别写成所有人的人生结论。数字必须有来源；具体数字不是每篇必备，也不能把原文「几次」加工成精确次数。

## 数据怎么参与

用户提供搜索截图、对标标题或自己的数据时，可以看目标读者是否用这种说法。给出样本范围与采集时间，不把一个账号的搜索结果当作平台全量事实。

没有样本时就按语义和正文检验标题，不假称验证过热度。没出现在搜索下拉或现有标题中，不证明这个表达没人需要；标题供给多也不证明用户的这篇会成功。

## 标题、首屏与封面

标题交代问题，首屏可以开始回答或把具体悬念摆出来，不用强行在第一句讲完结论。若标题问「为什么不敢交稿」，正文开头却介绍软件功能，读者的期待就落空了。

封面文字与正文要说同一件事。把细节留给正文，把最影响读者判断的词留在入口。没有现成图片时，只能建议画面内容，不能评价成品的清晰度或点击率。

用户未指定长度时给简洁版本；真正的字符限制以使用者当前编辑器为准，不能写死一个平台数字然后声称验证过。
